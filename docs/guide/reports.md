# Reports

## What this page is for

A report is the checked result of a run. Every claim in a report links to the records that support it.

## Who uses it

Each role sees its own report.

## How to use it

1. Open your report from the menu or from a run.
2. Select a claim's link to read the cited record.
3. Check the label on each item. It says where the data came from.

## The reports

| Report | For |
|---|---|
| Forecast | Product manager |
| Allocation | Engineering manager |
| Architecture | Solution architect |
| Security gate | Security engineer |
| Investigation | On-call engineer |

## Good to know

- A report can say that some items were held back. This happens when you do not have access to their sources.
- Forecast accuracy uses a stand-in for release blockers. See *proxy blocker* in the [glossary](glossary.md).
- If a later check removes a claim, the page marks the old report as replaced.
